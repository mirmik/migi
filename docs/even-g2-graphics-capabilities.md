# Графические возможности Even G2 для Migi

Проверено 2026-09-06. На очках: 2.2.9.22 / EVENCFW/17. Migi build38
использует штатный текстовый контейнер, обновляемый напрямую через BLE.
Это каталог интерфейсов, а не утверждение, что все функции испытаны на устройстве.

## Источники и уровни подтверждения

- Официальный `@evenrealities/even_hub_sdk` **0.0.14**, README и
  `dist/index.d.ts`, скачанные из npm без установки/выполнения:
  https://www.npmjs.com/package/@evenrealities/even_hub_sdk
- Декларации конкретной версии:
  https://unpkg.com/@evenrealities/even_hub_sdk@0.0.14/dist/index.d.ts
- BLE protobuf и построители команд:
  https://github.com/Commute773/g2-kit-unofficial/tree/main/ble
- CFW: https://github.com/jimrandomh/g2flash/blob/main/README.md
  и `patches/zlib_glue.c`; локально исследован checkout b20bfb1.
  Текущая ветка upstream не тождественна установленной CFW17.
- Migi: `even-g2-experiment.md`, результаты build38.

SDK работает через Even App WebView. Migi обходит этот мост и использует BLE;
поэтому SDK-модель, известный wire format и проверка установленной прошивки —
три разные стадии поддержки. Старые community notes (SDK0.0.9/0.0.10) уже
неполны: утверждения об отсутствии яркости текста и z-order устарели.

## Штатный путь EvenHub / LVGL

| Возможность | Что доступно | Состояние в Migi |
|---|---|---|
| Страница | Область576×288; до12 контейнеров, до8 текстовых; один захватывает ввод | Используем один текстовый и служебный image-контейнер |
| Текст | Позиция, размеры, обычный Unicode-текст; полная/частичная замена содержимого | Полная замена испытана; шрифт встроенный, покрытие символов требует проверки |
| Оформление | Рамка: толщина, оттенок, скругление; внутренний отступ у text/list | BLE поля5–8 известны; наш encoder пока их не передаёт |
| Список | Нативные элементы и рамка выделения, события выбранного элемента | Encoder уже есть для Faceclaw prompt; отдельный smoke Migi нужен |
| Изображение | Растровый контейнер, обновляемый отдельно от создания страницы | Raw BMP/LVGL испытан; большие кадры медленны |
| Наложение | `zOrderIndex`, большее значение ближе к зрителю; задан всем контейнерам либо ни одному, значения уникальны | SDK с0.0.12; в нашей старой protobuf-схеме поля нет |
| Яркость текста | `textColor`0–4, при создании/замене текста | SDK0.0.14; BLE-поле и CFW17 не проверены |
| Контекстное меню | До10 действий, имя до32UTF-8байт, ненулевые уникальные ID | SDK0.0.14; интеграции нет, CFW перехватывает некоторые жесты меню |
| Жесты | Click, scroll, doubleclick, lifecycle; новые SDK также longpress/release | Основные жесты и wake уже работают |

В актуальных декларациях нет выбора font family/size/weight/alignment, загрузки
TTF, произвольного canvas/path, линий/окружностей/полигонов, градиентов или
пользовательских LVGL-анимаций. Это ограничение доступного API, не самого LVGL.
Рамку можно создать штатным свойством контейнера; это не отдельный drawRect API.

ImageContainerProperty документирует **ширину20–288, высоту20–144**.
Наш576×288 image-carrier относится к расширенному пути CFW. Экспериментальный
1×1 carrier build37 был вне документированного диапазона и дал layout timeouts;
конкретная причина отказа не доказана. В build38 восстановлена рабочая геометрия.

SDK0.0.12+ сообщает LZ4 для передачи изображений. Это перспективный источник
формата для будущих маленьких иконок, но не подтверждение совместимости нашего
encoder с CFW17. Предыдущий stock-RLE эксперимент изображения не показал.

## Отдельный путь CFW: непосредственный framebuffer

CFW добавляет640×480, изменения прямоугольных участков, копирование областей,
кэш текстур64KiB, рисование кэшированных картинок/строк и встроенного шрифта:
mode12 upload, mode13 image, mode14 cached-font string, mode15 UTF-8 built-in font.
Установленная прошивка объявляет соответствующие capability tokens.

Это не LVGL-виджеты: modes13–15 изменяют shadow framebuffer и показывают его
напрямую. Upstream явно запрещает смешивать этот путь со штатными text/list
контейнерами. Нельзя считать его простым дополнением к нашему нынешнему
пейджеру или обещать сохранение штатного fade без отдельного исследования.

## Практическое направление

Для пейджера, файлов и плейлистов оставить штатные страницы: заголовок, тело или
список, статусная строка, небольшие растровые иконки. Разделить компоновку страницы
и обновления содержимого: текст менять без rebuild всей страницы; геометрию
пересоздавать при переходе между экранами. CFW framebuffer считать отдельным
рендерером, если понадобится произвольная графика.

Следующий hardware smoke: отдельная тестовая страница с text-рамкой и padding,
двумя текстовыми блоками и нативным списком; проверить выделение, scroll, выбор,
кириллицу, sleep/wake. Затем маленькая картинка рядом с текстом. Новые z-order,
textColor и menu требуют сначала установления BLE-полей, затем отдельного smoke.
В рамках этого исследования APK и прошивка не менялись.
